# 代码检查与修复记录 · 2026-10-18

范围：Windows 控制后端、公共坐标/图像接口、MCP stdio、请求取消、会话/截图状态与审计恢复。

## 已发现并修复

| 问题 | 修复与验证 |
| --- | --- |
| 暂停键使用系统为调试器保留的 F12 | 改为 Ctrl+Alt+F10；恢复仍为 Ctrl+Alt+F11，代码、CLI 帮助与文档同步。注册失败仍拒绝启动。 |
| MCP 取消只作用于当时的活动代次，排队请求和取消后新建 token 可能继续执行 | 请求入队即建立独立取消标记，覆盖排队、运行中与延迟创建的 token；不允许取消 initialize。新增 3 项回归测试。 |
| 截图或执行前预检失败后仍保留旧帧 | 清空旧帧和键盘焦点确认状态；必须重新观察。新增两项回归测试。 |
| 等待变化先重新截图作为基线，错过调用前已经发生的变化 | 优先对比有效的上一帧；零等待也能检测已发生变化。回归测试先在旧实现失败、修复后通过。 |
| 部分输入已发送却仍允许继续执行 | uncertain 结果自动触发 Agent 暂停，保留审计结果，等待核对后恢复。新增回归测试。 |
| 仅用前台 HWND 判断桌面是否可操作 | 增加当前 Windows 会话状态、输入桌面与线程桌面一致性检查；阻止断开会话、锁屏/安全桌面时输入。原生行为待 Windows 验证。 |
| 极端图像宽高计算可能整数溢出 | 使用 checked_mul，非法尺寸返回 INVALID_FRAME，不 panic。新增回归测试。 |
| 审计接口可写入无 intent 的 outcome，重复 intent 能覆盖已有状态 | 写入前拒绝无 intent 结果和重复 ID；加载时拒绝重复 intent。新增回归测试。 |
| 热键线程意外退出后仍可继续输入 | 消息循环退出即人工暂停；激活窗口循环支持取消。 |
| 原生错误处理不完整 | 检查 GdiFlush、遮挡窗口几何读取结果，保留热键注册失败时的原始错误。 |

F12 保留规则依据：[Microsoft RegisterHotKey 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)。

## 验证结果

- macOS / Rust 1.83：32 项测试通过（3 项 MCP 取消单元测试、28 项核心测试、1 项真实进程 stdio 测试）。
- Clippy：全部目标、包含 Windows API 检查特性，零警告通过。
- Windows 后端：使用 windows-sys 绑定进行类型检查；不能替代 Windows MSVC 链接、权限及实际远程客户端测试。
- 依赖验证使用本机已有源码的临时离线源配置，不把机器相关路径写入项目配置。

## 尚未验证 / 已知边界

- Windows 实机的截图、中文/快捷键转发、输入桌面检查及 F10/F11 热键需要执行 [验收矩阵](windows-validation.md)。
- 屏幕捕获和系统输入之间仍有竞态，像素变化阈值也不能识别所有语义变化；未实现同窗口物理键鼠接管。
- 当前窗口身份检查可以发现进程变化，不能保证识别同进程内的 HWND 复用或远程标签页切换。
- 同一个数据目录的 JSONL 审计不支持多个 Windows 登录会话同时写入，分别指定数据目录。
- OCR、后台捕获、GUI、Broker 等原有未实现范围保持不变。本次检查不将其标记为已完成。
